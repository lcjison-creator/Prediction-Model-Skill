# 临床预测模型全流程

## 这个 skill 解决什么问题

临床预测模型类论文被拒，绝大多数不是因为"模型不够先进"，而是因为方法学有洞：只报了 AUC 没报校准、没做内部验证、预处理泄露到了验证集、样本量撑不起变量数、用 SMOTE 之后还报校准曲线。本 skill 把一套经得起审稿的流程固化下来，让每个新课题都从同一个起点开始，而不是每次重新拼装。

用户是临床研究者，不是程序员。所有解释要用临床语言，不要甩术语。数字背后"意味着什么、有没有问题、审稿人会问什么"比数字本身更重要。

## 工作流

三步，按顺序走。**每一步做完先把结论讲给用户听，得到确认再进下一步**——尤其是第一步，如果数据本身撑不起建模，越早说越好。

### 第 1 步：数据质检（永远先做这步）

```bash
python scripts/audit_data.py --data <数据文件> --outcome <结局列名> --out <输出目录>
```

常用可选参数：`--exclude 住院号,姓名`（排除标识列）、`--categorical 性别,分型`（强制指定分类变量）、`--positive-label 1`（指定阳性标签）。

脚本产出 `audit.json`（机器读）和 `audit_report_zh.md`（人读）。读完之后，**用自己的话向用户汇报这几件事**：

- 多少例、多少个事件（阳性结局）、患病率多少
- EPV（每个参数对应多少事件）是多少，够不够
- 哪些变量缺失严重、哪些变量几乎是常量、哪些变量之间高度共线
- 脚本推荐了哪种验证策略，为什么

**如果脚本报了 `blocking` 级别的问题（比如事件数 < 20），不要绕过去继续建模。** 直接告诉用户样本量撑不起来，硬做出来的 AUC 是假的，并给出可行方向：减少变量、合并结局定义、扩大队列、或者改做描述性研究。研究者宁愿现在听到坏消息，也不愿意在审稿意见里听到。

### 第 2 步：建模与验证

```bash
python scripts/run_pipeline.py --data <数据文件> --outcome <结局列名> --out <输出目录>
```

默认行为已经是方法学上的稳妥选择，通常不需要改。可选参数：`--models lr,rf,xgb`、`--strategy auto|bootstrap|split`、`--seed 42`、`--n-boot 500`、`--exclude`、`--categorical`。

脚本会自动做这些事，理由写在 `references/methodology.md` 里，用户追问时去查：

- **把所有预处理装进 sklearn Pipeline**（填补、编码、标准化都在 Pipeline 内），这样交叉验证和 bootstrap 的每一折都只用该折的训练数据拟合填补器。手动先填补整个数据集再切分是数据泄露，是这类论文最常见的致命错误。
- **强制包含 Logistic 回归作为基准模型**。审稿人一定会问"机器学习比传统回归好在哪"，没有基准就没法回答。如果 XGBoost 只比 Logistic 高 0.01 AUC，诚实的结论是"传统回归已经够用"，这本身就是有价值的发现。
- **概率校准**：样本量小用 sigmoid（Platt），大用 isotonic，脚本自动选。
- **验证策略按第 1 步的 EPV 自动决定**：样本紧张时用全数据训练 + bootstrap 乐观度校正（Harrell 法），而不是硬切一个小得没有统计意义的测试集。
- **完整指标**：区分度（AUC 及 95%CI、敏感度/特异度/PPV/NPV）、校准（校准斜率、截距、Brier score、校准曲线）、临床效用（决策曲线净获益）。三类缺一不可——只报 AUC 是最常见的退稿理由。
- **模型间 DeLong 检验**，回答"这个模型真的比那个好吗"。

### 第 3 步：出图与报告

```bash
python scripts/make_plots.py --results <输出目录>
```

产出 300 dpi TIFF + 矢量 PDF 双份：ROC 曲线（多模型叠加）、校准曲线、决策曲线、SHAP 蜂群图与重要性图。

**变量名是中文时必须做一步中英对照。** 脚本第一次运行会检测到中文变量名，自动生成 `labels_template.json`，里面每行是「中文名: 中文名」。把右边改成英文术语（分类变量的各个水平也要改，比如"暴发性心肌炎" → "Fulminant myocarditis"），另存为输出目录下的 `labels.json`，再跑一次脚本，图里就全是英文了。

**主动帮用户填这份对照表**——临床术语的标准英文译法（NT-proBNP、Fractional shortening、Vasoactive agents）你比用户更熟，直接写好让他们过目修改，比让他们从零查更省事。填完记得重跑 `make_plots.py`。

如果环境里没有中文字体，未翻译的中文会渲染成方框，脚本会明确警告。这种"图生成成功了但完全不能用"的情况必须提醒用户，不要默默交付。

然后**你来写中文解读报告**，写到 `<输出目录>/report_zh.md`。脚本已经把自动检出的问题放在 `findings.json` 里，但解读要你写——这是这个 skill 里最需要判断力的部分，不要交给模板。按这个结构：

```markdown
# <课题名称> 预测模型结果解读

## 一句话结论
（这个模型能不能用、能不能发，直说）

## 数据概况
（例数、事件数、EPV、缺失情况，一段话）

## 模型表现
### 区分度
（AUC 多少、95%CI 多宽、跟 Logistic 基准比如何。AUC 的临床含义要说人话：
"随机抽一个发生结局的病人和一个没发生的，模型给前者更高分的概率是 XX%"）
### 校准
（校准斜率和截距意味着什么。斜率 < 1 说明预测被拉得过散、有过拟合迹象；
截距偏离 0 说明整体高估或低估风险。这是审稿人最爱抓的地方）
### 临床效用
（决策曲线在哪个阈值区间比"全治"和"全不治"更优，对应什么临床场景）

## 需要注意的问题
（逐条列 findings.json 里的问题，每条说清楚：是什么、为什么要紧、怎么办）

## 审稿人可能会问什么
（针对本次结果的具体薄弱点，预判 3-5 个问题并给出应答思路）

## 下一步建议
```

同时把 `references/tripod_ai_checklist.md` 复制到输出目录，逐条填上本次研究的对应情况——投稿时很多期刊要求随稿提交。

## 需要坚持的几条底线

这些不是形式主义，每一条都对应一类真实的退稿理由：

**不要为了好看的数字牺牲诚实。** 如果模型表现平平，就如实说平平，并分析原因（变量信息量不足？结局定义太宽泛？样本异质性太大？）。把 AUC 从 0.72 调到 0.85 的常见手段——反复换种子挑最好的、把测试集信息漏进训练、在全数据上调参——产出的都是发表后无法复现的结果。

**类别不平衡不要默认上 SMOTE。** SMOTE 会系统性抬高预测概率，让校准曲线彻底失真，而校准恰恰是临床模型的命门。优先用 `class_weight='balanced'` 或直接调整决策阈值。如果用户坚持要用 SMOTE，可以做，但必须在报告里说明校准结果不可信。

**变量筛选不能看着结局挑。** 先用单因素分析在全数据上筛一遍再建模，等于让测试集信息提前泄露。变量筛选要么基于临床先验知识（推荐，也最好写进论文），要么放进 Pipeline 内部在每折训练集里做。

**报告随机种子和软件版本。** 脚本已经把这些写进 `model_card.json`，写论文时要用。

**模型是辅助工具，不是诊断结论。** 生成的任何面向使用者的产物（包括后续的网页计算器），都要带上"仅供科研与临床辅助参考，不能替代医师判断"的声明。

## 输出物清单

跑完三步后，输出目录里应该有：

| 文件 | 用途 |
|---|---|
| `audit_report_zh.md` | 数据质检报告 |
| `metrics.csv` / `metrics.json` | 所有模型的完整指标表 |
| `figures/*.tiff` / `*.pdf` | 期刊级图，直接投稿 |
| `report_zh.md` | 中文解读（你写的） |
| `TRIPOD_AI_checklist.md` | 投稿自查清单 |
| `model_bundle.pkl` | 训练好的模型 + 预处理管线，一个文件搞定 |
| `model_card.json` | 特征顺序、版本、种子、训练参数——做网页计算器时要用 |

`model_bundle.pkl` 里存的是完整 Pipeline，加载后直接 `predict_proba(原始格式的DataFrame)` 即可，不需要使用者自己再做填补和编码。用户后续要做 Streamlit 计算器时，从这个文件和 `model_card.json` 出发。

## 参考文件
