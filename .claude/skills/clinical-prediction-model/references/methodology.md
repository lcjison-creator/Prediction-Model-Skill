## 1. 样本量与 EPV

**EPV（events per variable）= 少数类事件数 ÷ 模型参数个数。**

注意分母是**参数**不是变量：一个有 4 个水平的分类变量占 3 个参数，不是 1 个。分子取阳性和阴性中**少的那个**——如果 1000 例里 950 例死亡，限制模型的是那 50 例存活。

经验下限是 10，稳妥是 20。低于 10 时模型开始记住噪声：它在训练数据上表现出色，换一批病人就失效。这正是大量"AUC 0.9"的预测模型无法被别人复现的原因。

事件数低于 20 时，本 skill 会直接拦截。这不是保守，是因为在那个量级上，多变量模型的任何结果都只是随机波动的产物。

**样本不够时的出路**（按推荐顺序）：
1. 按临床先验知识砍变量，只留最有把握的几个
2. 合并相近的结局定义，让事件数上升（比如"死亡"扩成"死亡或需要 ECMO"）
3. 多中心协作扩大队列
4. 改做描述性研究或单因素分析，如实报告

Riley 等人提出的最小样本量计算法比 EPV 更精细，考虑了预期 R²、患病率和可接受的过拟合程度。EPV 更简单，作为初筛够用。

## 2. 缺失值处理

**填补必须在 Pipeline 内部按折进行。** 先在全数据上跑一遍填补再切分训练/测试，测试集的信息就通过填补器的中位数漏进了训练过程——这是数据泄露，会让验证结果虚高，而且是这类论文最常见的方法学硬伤。本 skill 把 `SimpleImputer` 放进 `sklearn.Pipeline`，交叉验证和 bootstrap 的每一折都只用当次训练数据拟合填补器，结构上杜绝了这个问题。

**连续变量用中位数，不用均值。** 临床检验指标（NT-proBNP、CRP、肌钙蛋白、肌酐）普遍右偏且有极端值，均值会被拉偏。

**缺失率超过 40% 的变量直接剔除。** 这时候填补出来的值主要反映填补算法而不是病人。如果这个变量临床上非留不可，换个思路：把它转成"是否做了这项检查"的二分类变量——在真实临床数据里，做没做某项检查本身往往就携带信息（医生觉得有必要才查）。

**要在论文里说明缺失机制。** 是完全随机缺失（MCAR）、随机缺失（MAR）还是非随机缺失（MNAR）？临床数据大多是 MAR 或 MNAR。多重填补（MICE）在方法学上比单次填补更严谨，如果审稿人要求，可以作为敏感性分析补充。

## 3. 验证策略怎么选

| 情况 | 策略 | 原因 |
|---|---|---|
| 事件 < 20 | 不建模 | 任何结果都不可信 |
| EPV < 10 或 n < 500 | 全数据训练 + bootstrap 乐观度校正 | 切出的测试集太小，AUC 置信区间宽到没有意义，还白白损失训练数据 |
| n ≥ 500 且 EPV ≥ 10 | 切 25~30% 独立验证集 + 训练集内 bootstrap | 数据够用，独立验证集更直观、更容易被审稿人接受 |

**Bootstrap 乐观度校正（Harrell 法）的原理**：在原始数据上训练又在同一批数据上评估，结果必然偏乐观。做法是重抽样一个 bootstrap 样本、在上面重新训练，然后比较该模型在 bootstrap 样本上（乐观）和在原始数据上（相对客观）的表现，两者之差即"乐观度"，平均 B 次后从表观性能里减掉。

它比简单切分更适合小样本，因为不浪费任何一例数据，而且用上了全部信息来估计乐观度。B 一般取 200~1000。

**内部验证不能替代外部验证。** 无论 bootstrap 还是切分，都只说明模型在**当前这批病人**上站得住。要证明能推广到别的医院、别的年代、别的人群，必须有外部队列。论文的局限性部分必须写清楚这一点——主动写出来比被审稿人指出来好得多。

## 4. 为什么必须做概率校准

区分度（AUC）回答"模型能不能把高危和低危病人排开"，校准回答"模型说的 30% 风险，是不是真的有 30% 的人出事"。

**临床上后者往往更要紧。** 一个 AUC 0.85 但系统性高估两倍风险的模型，会让医生对一大批实际低危的孩子过度干预。而 AUC 只关心排序，对整体高估或低估完全不敏感——两个模型可以有一模一样的 AUC，一个校准完美一个离谱。

树模型（随机森林、XGBoost）的原始输出天生校准很差，必须校准。本 skill 用 `CalibratedClassifierCV`：

- **小样本用 sigmoid（Platt scaling）**：只拟合两个参数，稳健
- **大样本用 isotonic（保序回归）**：更灵活，但在小样本上自己就会过拟合，阈值设在事件 ≥ 100 且总例数 ≥ 1000

参数上用 `ensemble=False`，让基模型在全部训练数据上训练一次、校准器在折外预测上拟合。默认的 `ensemble=True` 会把 k 折模型的概率平均，这种平均把预测值向均值收缩，会人为制造出大于 1 的校准斜率，反而把真实的过拟合程度掩盖掉。

## 5. 三类指标怎么读

只报 AUC 是最常见的退稿理由。完整的临床预测模型报告需要三类指标。

### 区分度（Discrimination）

**AUC / C-statistic**：随机抽一个发生结局的病人和一个没发生的，模型给前者更高分的概率。0.5 = 瞎猜，1.0 = 完美。

粗略参考：< 0.7 区分能力不足；0.7~0.8 可接受；0.8~0.9 良好；> 0.9 优秀，**但同时要警惕**——在小样本临床数据上出现 0.95 以上，先怀疑数据泄露或结局定义里混进了预测变量的信息（比如用"是否使用 ECMO"预测"死亡"，而 ECMO 本身是濒死状态的标志）。

**一定要报 95% 置信区间。** n=200 的研究里 AUC 0.82 的置信区间可能是 0.74~0.90，跟 0.75 的模型根本分不开。

**敏感度/特异度/PPV/NPV** 依赖于选定的阈值。约登指数（敏感度+特异度-1 最大）是常用的取法，但临床上阈值该定在哪，取决于漏诊和误诊哪个代价更高——漏诊一例暴发性心肌炎的代价远高于多观察一个孩子，这种场景应当牺牲特异度保敏感度。**PPV 和 NPV 随患病率变化**，在低患病率人群里 PPV 会大幅下降，这点必须在讨论里说明。

### 校准（Calibration）

**校准斜率**：理想值 1.0。
- < 0.8：预测值过于分散，高风险估得太高、低风险估得太低——过拟合的典型表现
- > 1.2：预测值过于集中在患病率附近，模型没有拉开风险差距

**校准截距（calibration-in-the-large）**：理想值 0。偏离说明整体高估或低估了风险水平。把模型移植到患病率不同的人群时，通常只需要重新校准截距，斜率和变量系数可以保留。

**Brier score**：预测概率与实际结局的均方差，越小越好，同时反映区分度和校准。它对患病率敏感，跨研究比较意义有限，主要用于同一数据上比较不同模型。

**Hosmer-Lemeshow 检验**：p > 0.05 表示"没有检出显著的校准偏差"。局限很大——样本量大时几乎必然显著，样本量小时几乎必然不显著，而且结果依赖分组数。只作参考，**校准曲线和校准斜率才是主要依据**。

### 临床效用（Clinical utility）

**决策曲线分析（DCA）** 回答的是 AUC 回答不了的问题：用这个模型做决策，比"全都干预"或"全都不干预"到底好多少？

它把假阳性按 `t/(1-t)` 的权重折算后从真阳性里扣除，得到净获益。阈值概率 t 隐含了医生的价值判断：t = 10% 意味着"愿意为找出 1 个真阳性而承受 9 个假阳性"。

读图方式：在临床上合理的阈值区间内，模型曲线明显高于"全治"和"全不治"两条线，才说明这个模型真的有用。**很多 AUC 看着不错的模型在 DCA 上没有净获益**，这也是审稿人越来越常要求 DCA 的原因。

## 6. 类别不平衡：为什么不推荐 SMOTE

SMOTE 通过在少数类样本之间插值来合成新样本，改变了训练集的类别比例，因此**模型输出的概率不再对应真实的患病率——它会系统性高估风险**。

结果是校准曲线彻底失真。而校准恰恰是临床预测模型的核心指标。用了 SMOTE 还报告校准曲线，是自相矛盾的。

**推荐做法**：
1. `class_weight='balanced'`（本 skill 在少数类占比 < 25% 时自动启用）——只改变损失函数权重，不伪造样本
2. 直接调整决策阈值——大多数"不平衡问题"本质上是默认阈值 0.5 不合适，而不是数据本身有问题
3. 用对不平衡不敏感的指标：AUC、PR 曲线下面积，而不是准确率

**如果用户坚持要用 SMOTE**：可以做，但必须在报告里写明校准结果不可信，并且只能报告区分度指标。

## 7. 变量筛选的陷阱

**用单因素分析在全数据上筛变量，再拿筛出来的变量建模验证，是数据泄露。** 筛选过程已经看过了全部结局信息，后面的交叉验证或切分验证都被污染了，结果会系统性偏乐观。这个错误极其普遍，但确实是错的。

正确做法，按推荐顺序：

1. **基于临床先验知识选变量**（最推荐）。既避免了泄露，也让模型更容易被同行接受——审稿人喜欢看到"我们基于既往文献和病理生理选择了这些变量"，而不是"我们让算法自己挑"。写进论文里也更好看。
2. **把筛选步骤放进 Pipeline 内部**，在每折训练集里独立执行。方法学上正确，但实现更复杂，且每折选出的变量可能不同，最终模型不好解释。
3. **用正则化代替显式筛选**。LASSO 或岭回归在拟合过程中自动收缩不重要的系数，天然属于模型的一部分，不存在泄露问题。

另外：**不要反复换随机种子挑最好的那次结果**。这等于在噪声上做选择，产出的是发表后无法复现的数字。本 skill 把种子固定写进 `model_card.json`，就是为了让结果可复现。

## 8. 常见审稿意见与应对

**"样本量是否足够？"**
→ 报告 EPV 和事件数。不够就承认，并说明已通过限制变量个数、加强正则化来控制过拟合，同时给出了 bootstrap 校正后的性能。

**"为什么用机器学习而不是传统 Logistic 回归？"**
→ 这就是必须跑 Logistic 基准的原因。如果 XGBoost 只比 Logistic 高 0.01 AUC，诚实的回答是"传统回归已经足够，我们推荐使用更易解释的 Logistic 模型"——这本身是有价值的结论，而且临床上更受欢迎。如果确实高出不少，用 DeLong 检验给出差异的 p 值。

**"有没有做外部验证？"**
→ 内部验证不能替代外部验证。没有就在局限性里明确写出来，并说明这是模型开发阶段的研究。主动承认比被指出来好。

**"模型如何处理缺失值？"**
→ 说明填补方法，并强调填补在 Pipeline 内按折进行、没有数据泄露。这一句话能挡掉很多质疑。

**"校准怎么样？"**
→ 给出校准曲线、校准斜率和截距、Brier score。只报 AUC 一定会被追问。

**"这个模型临床上真的有用吗？"**
→ 决策曲线分析。指出在临床合理的阈值区间内，模型的净获益高于全治和全不治策略。

**"AUC 这么高，是不是有信息泄露？"**
→ 检查预测变量里有没有混进结局的替代指标（用 ECMO 预测死亡、用 ICU 住院天数预测预后）。这类变量在临床上是结局的一部分，不能当预测因子。

**"结果能复现吗？"**
→ 报告随机种子、软件版本、完整的超参数。`model_card.json` 里都有。
